Outputs: `data/bakeoff/<converter>/<file>.md`. CPU only.

- **Coverage**: share of the PyMuPDF plain-text extraction's characters, counted as whole words, that appear in the Markdown.
  pymupdf4llm uses the same text engine as the baseline, so its coverage is biased upward;
  coverage does not measure reading order or tables, and above 100% is not possible.
  Pages with no text layer (scans, images) are missing from the baseline, so OCR text there earns no credit.
- **Tables**: Markdown pipe tables (separator rows). **Headings**: `#` lines.
- **Time**: per-file conversion time; model loading is excluded and listed separately.

## Decision

**pymupdf4llm is primary; Docling (OCR only on pages without a text layer) is the fallback for files that fail quality checks; Marker is dropped.**
This section is hand-written; `report` keeps it when regenerating the tables above.

Marker was dropped because it lost ~10% of text on both 29-page files, crashed on a file with near-blank pages (a Marker bug), and has GPL code with a restrictive model license.

| Merged wrongly (real compound glued together) | ~20 | ~14 distinct |

Images (70 found by Docling in 9 files): 62 logos, 1 title banner, 6 photos without meaningful text, and 1 full-page text graphic (~200 words) with no text layer. pymupdf4llm OCR'd the text graphic (~174 words) and kept the banner text; Docling kept neither.

Extra text in pymupdf4llm output (page numbers, running headers, logo text, disclaimers) is removable by rule: margin-repeat removal (first/last 3 lines, 2+ pages, keep first copy, skip table rows) plus standalone page-number lines left no real boilerplate behind. Without "keep first copy" and "skip table rows" the rule deleted 2 table separator rows, a title heading, and a one-time policy line. Docling also kept running headers on some files, so the same rules apply to both. Cleanup rules: DESIGN.md Section 11.3.
